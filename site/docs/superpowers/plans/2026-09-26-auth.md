# Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Working email+password and Google login through Neon Auth, with every piece of our own authorization logic covered by Vitest unit tests.

**Architecture:** One file (`lib/auth/server.ts`) creates the Neon Auth SDK instance. One file (`lib/auth/session.ts`) calls `auth.getSession()` and converts the result into our own `SessionUser`, failing closed. Guards (`requireUser`, `requirePageUser`), a pure `assertOwner`, and `toErrorResponse` sit on top, and tests mock only `session.ts` (or `server.ts` when testing `session.ts` itself). The UI is the prebuilt `@neondatabase/auth-ui` `AuthView`. `proxy.ts` gives an optimistic redirect for `/dashboard`, but the real checks are in the guards.

**Tech Stack:** Next.js 16.3.6 (App Router, `proxy.ts`), React 19, TypeScript strict, Tailwind v4, pnpm, `@neondatabase/auth@0.5.0-beta`, `@neondatabase/auth-ui@0.3.0-beta`, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-26-auth-design.md`

All paths and commands are relative to `site/` (the Next.js app; the git root is its parent `UGCEditor/`). The working branch is `auth`.

## Review Focus

1. **A missing or too-short `NEON_AUTH_COOKIE_SECRET` or `NEON_AUTH_BASE_URL`**: the app must fail at startup with an error naming the variable, not at a user's first request. Pinned by `tests/lib/auth/server.test.ts` (Task 2).
2. **The SDK returning an `error` alongside non-null `data`**: the error must win (fail closed). Pinned in `tests/lib/auth/session.test.ts` (Task 2).
3. **A thrown non-`Error` value (a string) reaching `toErrorResponse`**: it must be rethrown unchanged, not turned into a 401 or 404. Pinned in `tests/lib/auth/errors.test.ts` (Task 1).
4. **`/dashboard` with a query string, and look-alike paths such as `/dashboard-old`**: the first must be protected; the second must not match the proxy. Pinned in `tests/proxy.test.ts` (Task 5).
5. **An unauthenticated `fetch` to a protected API route**: it must get a JSON 401, not a redirect to an HTML sign-in page. Pinned by `/api/me` not matching the proxy (Task 5) and the route returning 401 (Task 4).

Create `lib/auth/errors.ts`:

```ts
export class UnauthorizedError extends Error {
  constructor() {
    super("Unauthorized");
    this.name = "UnauthorizedError";
  }
}

// Used for both "doesn't exist" and "belongs to someone else", so responses
// never reveal whether another user's resource exists.
export class NotFoundError extends Error {
  constructor() {
    super("Not found");
    this.name = "NotFoundError";
  }
}

export function toErrorResponse(e: unknown): Response {
  if (e instanceof UnauthorizedError) {
    return Response.json({ error: "Unauthorized" }, { status: 401 });
  }
  if (e instanceof NotFoundError) {
    return Response.json({ error: "Not found" }, { status: 404 });
  }
  throw e;
}
```

Create `lib/auth/session.ts`:

```ts
import { auth } from "@/lib/auth/server";

export type SessionUser = { id: string; email: string; name: string };

// Fails closed: any SDK error or exception is treated as "not signed in".
export async function getCurrentUser(): Promise<SessionUser | null> {
  try {
    const { data, error } = await auth.getSession();
    if (error) {
      console.error("[auth] getSession returned an error", error);
      return null;
    }
    const user = data?.user;
    if (!user) return null;
    return { id: user.id, email: user.email, name: user.name };
  } catch (e) {
    console.error("[auth] getSession threw", e);
    return null;
  }
}
```

```ts
import { redirect } from "next/navigation";
import { UnauthorizedError } from "@/lib/auth/errors";
import { getCurrentUser, type SessionUser } from "@/lib/auth/session";

export const SIGN_IN_PATH = "/auth/sign-in";

// For route handlers and server actions. Pair with toErrorResponse.
export async function requireUser(): Promise<SessionUser> {
  const user = await getCurrentUser();
  if (!user) throw new UnauthorizedError();
  return user;
}

// For pages. Never assumes proxy.ts already ran.
export async function requirePageUser(): Promise<SessionUser> {
  const user = await getCurrentUser();
  if (!user) redirect(SIGN_IN_PATH);
  return user;
}
```
